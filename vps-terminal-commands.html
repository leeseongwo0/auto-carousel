Newsbot VPS 터미널 명령 순서

Ubuntu VPS에서 위에서 아래로 실행합니다. 명령 블록 오른쪽의 복사 버튼을 사용할 수 있습니다.

먼저 확인: 이 문서는 현재 구현된 기능을 설치하고 수동 End-to-End 검증하는 순서입니다. 전체 수집·알림·polling·Sheets 전달을 주기 실행하는 timer는 아직 없고 Codex 생성 timer만 있습니다.

입력해야 할 값

아래 값은 명령에 그대로 입력하지 말고 해당 편집 화면에서 실제 값으로 바꿉니다.

  • TELEGRAM_API_ID, TELEGRAM_API_HASH
  • TELEGRAM_BOT_TOKEN
  • NEWSBOT_APPROVER_CHAT_ID, NEWSBOT_APPROVER_USER_IDS
  • GOOGLE_SHEETS_SPREADSHEET_ID
  • Google service-account JSON 전체

1필수 패키지 설치

sudo apt update
sudo apt install -y git sqlite3 ca-certificates python3 python3-venv nodejs npm

5환경 파일 입력

다음 명령을 실행하고 편집기에 아래 내용을 붙여 넣은 뒤 빈 값을 채웁니다.

sudo install -o newsbot -g newsbot -m 0600 /dev/null /etc/newsbot/newsbot.env
sudoedit /etc/newsbot/newsbot.env
TELEGRAM_API_ID=
TELEGRAM_API_HASH=
TELEGRAM_SESSION_PATH=/var/lib/newsbot/telegram/newsbot.session
TELEGRAM_BOT_TOKEN=
NEWSBOT_APPROVER_CHAT_ID=
NEWSBOT_APPROVER_USER_IDS=
GOOGLE_SHEETS_SPREADSHEET_ID=

6SQLite 운영 DB 생성

sudo -u newsbot /usr/local/bin/newsbot init-db --db /var/lib/newsbot/newsbot.db
sudo -u newsbot sqlite3 /var/lib/newsbot/newsbot.db \
  "SELECT version FROM schema_migrations ORDER BY version;"
sudo -u newsbot sqlite3 /var/lib/newsbot/newsbot.db "PRAGMA foreign_key_check;"
sudo stat -c '%U:%G %a %n' /var/lib/newsbot/newsbot.db
PRAGMA foreign_key_check가 아무것도 출력하지 않으면 정상입니다.

11보안 policy gate — 여기서 확인 없이 넘어가지 않기

현재 저장소에는 VPS별 /etc/codex/requirements.toml 완성본과 실제 effective-policy canary가 없습니다. Codex child가 auth, Newsbot 파일, network, web, MCP, plugin, socket 및 /proc 경로에 접근하지 못한다는 검증 전에는 production timer를 켜면 안 됩니다.
sudoedit /etc/codex/requirements.toml
sudo chown root:root /etc/codex/requirements.toml
sudo chmod 0644 /etc/codex/requirements.toml

# 모든 Codex unit이 inactive이고 cgroup이 비어 있음을 확인한 뒤에만 실행
sudo /usr/local/sbin/newsbot-codex-containment-v1 reset
sudo /usr/local/sbin/newsbot-codex-containment-v1 inspect

12수집→랭킹→Telegram 후보 질문

sudo -u newsbot -H bash
set -a
source /etc/newsbot/newsbot.env
set +a

/usr/local/bin/newsbot collect-live \
  --config /etc/newsbot/config.toml \
  --db /var/lib/newsbot/newsbot.db \
  --lookback-hours 24 --page-size 50 --max-pages 2

/usr/local/bin/newsbot rank \
  --config /etc/newsbot/config.toml \
  --db /var/lib/newsbot/newsbot.db

# 위 출력의 run_id와 승인자 user ID를 넣습니다.
/usr/local/bin/newsbot notify-candidates \
  --db /var/lib/newsbot/newsbot.db \
  --run-id RUN_ID --actor-id APPROVER_USER_ID

# Telegram에서 [제작]을 누른 뒤 callback을 처리합니다.
/usr/local/bin/newsbot poll-approvals \
  --config /etc/newsbot/config.toml \
  --db /var/lib/newsbot/newsbot.db --timeout 20
exit

14원고 알림→최종 승인→Sheets 전달

sudo -u newsbot -H bash
set -a
source /etc/newsbot/newsbot.env
set +a

/usr/local/bin/newsbot notify-review \
  --db /var/lib/newsbot/newsbot.db \
  --candidate-id CANDIDATE_ID --generation-id GENERATION_ID \
  --actor-id APPROVER_USER_ID

# Telegram에서 [시트 전달]을 누른 뒤 실행합니다.
/usr/local/bin/newsbot poll-approvals \
  --config /etc/newsbot/config.toml \
  --db /var/lib/newsbot/newsbot.db --timeout 20

sqlite3 -header -column /var/lib/newsbot/newsbot.db \
  "SELECT id AS handoff_id,status FROM sheet_handoffs ORDER BY id DESC LIMIT 5;"

/usr/local/bin/newsbot sheets-deliver \
  --config /etc/newsbot/config.toml \
  --db /var/lib/newsbot/newsbot.db --handoff-id HANDOFF_ID

/usr/local/bin/newsbot sheets-status \
  --config /etc/newsbot/config.toml \
  --db /var/lib/newsbot/newsbot.db
exit

15Codex timer 활성화

이 timer는 승인된 Codex job 생성만 반복합니다. 채널 수집, 후보 알림, callback polling, 원고 알림, Sheets delivery는 아직 수동입니다.
# 보안 policy/negative canary와 1회 live 검증이 모두 성공한 경우에만 실행
sudo systemctl enable --now newsbot-generate-codex.timer
sudo systemctl list-timers newsbot-generate-codex.timer
sudo /usr/local/sbin/newsbot-codex-containment-v1 inspect

문제가 생기면

sudo systemctl disable --now newsbot-generate-codex.timer
sudo systemctl status newsbot-generate-codex.service --no-pager
sudo journalctl -u newsbot-generate-codex.service -n 100 --no-pager
sudo /usr/local/sbin/newsbot-codex-containment-v1 inspect
sudo -u newsbot /usr/local/bin/newsbot status --db /var/lib/newsbot/newsbot.db

DB row, provider event, containment receipt를 삭제하거나 과거 DB로 덮어쓰지 않습니다.
