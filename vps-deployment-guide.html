Newsbot V2 VPS 운영 가이드

이 문서는 activation 17에서 V2로 전환한 뒤 Telegram 수집·2단계 승인, Codex 생성, Google Sheets 전달을 운영하는 절차입니다. 기존 Newsbot DB와 이력은 root-owned read-only archive이며 운영 명령의 입력으로 다시 사용하지 않습니다.

중요: 공개 저장소의 합성 채널 설정은 운영 설정이 아닙니다. 비공개 환경 값은 운영자가 별도로 검토·제공하며 secret은 terminal, 문서, log에 붙여 넣지 않습니다. Telegram·Sheets·Codex 효과가 ambiguous하면 자동으로 명령을 다시 실행하지 않습니다.

1. 소스 갱신과 release 변수

sudo git -C /opt/newsbot/current pull --ff-only origin main
cd /opt/newsbot/current
export RELEASE_GIT_SHA=REPLACE_WITH_APPROVED_40_HEX_COMMIT_SHA
export UV_SHA256=REPLACE_WITH_APPROVED_UV_ARTIFACT_SHA256
export RELEASE_DIGEST=SET_AFTER_BUILD_FROM_RUNTIME_MANIFEST_SHA256
export PROPOSAL_ID=REPLACE_WITH_NEW_OPERATOR_PROPOSAL_ID
sudo install -d -o root -g root -m 0755 /opt/newsbot/releases/$RELEASE_GIT_SHA/src
sudo git -C /opt/newsbot/current archive $RELEASE_GIT_SHA | sudo tar -x -C /opt/newsbot/releases/$RELEASE_GIT_SHA/src
sudo chown -R root:root /opt/newsbot/releases/$RELEASE_GIT_SHA

Git commit과 artifact digest는 승인된 release record에서 얻습니다. source tree, DB, session, Google JSON을 서로 복사하지 않습니다.

2. 기존 호스트와 V2 authority 확인

sudo test "$(stat -c '%U:%G %a' /var/lib/newsbot)" = "root:newsbot 750"
sudo test "$(stat -c '%U:%G %a' /var/lib/newsbot/newsbot.db)" = "root:newsbot 440"
sudo test "$(stat -c '%U:%G %a' /var/lib/newsbot-v2)" = "newsbot:newsbot 700"
sudo -u newsbot test -r /var/lib/newsbot-v2/newsbot-v2.sqlite
sudo test "$(stat -c '%U:%G %a' /etc/newsbot/newsbot.env)" = "root:newsbot 640"
sudo -u newsbot test -r /etc/newsbot/newsbot.env
sudo -u newsbot test -r /var/lib/newsbot/telegram/newsbot.session
sudo -u newsbot test -r /var/lib/newsbot/google/service-account.json

계정, 세션, service-account, V2 DB는 이미 provision된 운영 자산입니다. 일반 release에서 다시 만들거나 소유권을 바꾸지 않습니다. legacy 디렉터리와 DB를 newsbot 소유 또는 쓰기 가능 상태로 되돌리는 release는 거부합니다.

3. 환경과 adapter 사전 확인

sudo -u newsbot -H bash -c '
  set -a
  . /etc/newsbot/newsbot.env
  set +a
  test -n "$NEWSBOT_V2_TELEGRAM_HANDLES"
  test -n "$TELEGRAM_BOT_TOKEN"
  test -n "$NEWSBOT_CALLBACK_ACTOR_ID"
  test -n "$GOOGLE_SHEETS_SPREADSHEET_ID"
'
sudo systemctl cat newsbot-collect.service newsbot-telegram.service newsbot-sheets.service \
  | grep -F -- '/var/lib/newsbot-v2/newsbot-v2.sqlite'
sudo systemctl cat newsbot-generate-codex.service \
  | grep -F -- 'generate-codex-v2-once --db /var/lib/newsbot-v2/newsbot-v2.sqlite'

credential 값은 출력하지 않고 존재 여부와 owner-only 파일 권한만 확인합니다. adapter의 실제 원격 효과는 승인된 작업을 처리하면서 durable V2 receipt로 검증하며, 진단을 위해 Telegram 메시지나 Sheets 행을 별도로 전송하지 않습니다.

4. 향후 release의 quiescence와 versioned switch

sudo systemctl disable --now newsbot-collect.timer newsbot-telegram.timer newsbot-sheets.timer newsbot-generate-codex.timer
for unit in newsbot-collect.service newsbot-telegram.service newsbot-sheets.service newsbot-generate-codex.service; do
  test "$(systemctl is-active "$unit" || true)" = inactive
done
sudo /usr/local/sbin/newsbot-codex-containment-v1 inspect
sudo sh -c 'cd /var/lib/newsbot-legacy-archive/activation-17 && sha256sum -c SHA256SUMS'
sudo test "$(stat -c '%U:%G %a' /var/lib/newsbot/newsbot.db)" = "root:newsbot 440"

activation 17 이전의 release helper는 writable legacy DB와 legacy lock authority를 요구할 수 있으므로 archive 경계를 지원한다는 검토 증거 없이 재사용하지 않습니다. helper가 legacy DB를 newsbot:newsbot 0600으로 되돌리거나 legacy activation을 append하려 하면 release를 중단하고 별도 검토 PR에서 V2-only build/switch 경계를 수정합니다. 승인된 commit과 runtime manifest digest가 고정된 release만 switch하며, legacy archive 권한은 변경하지 않습니다.

5. Legacy archive attestation

LEGACY_ARCHIVE=/var/lib/newsbot-legacy-archive/activation-17
sudo test "$(stat -c '%U:%G %a' /var/lib/newsbot)" = "root:newsbot 750"
sudo test "$(stat -c '%U:%G %a' /var/lib/newsbot/newsbot.db)" = "root:newsbot 440"
sudo test "$(stat -c '%U:%G %a' "$LEGACY_ARCHIVE")" = "root:newsbot 750"
sudo sh -c "cd '$LEGACY_ARCHIVE' && sha256sum -c SHA256SUMS"
sudo sqlite3 -readonly /var/lib/newsbot/newsbot.db \
  "SELECT next_offset FROM telegram_update_cursors WHERE stream='approval';"

activation 17 이후 legacy DB·config·runtime manifest·unit은 운영 입력이 아닌 root-owned read-only archive입니다. newsbot UID는 legacy DB와 상위 디렉터리를 변경하거나 교체할 수 없어야 합니다. 이후 release, rollback, 상태 확인에서 init-db, migration, cutover preview/apply, release activation 또는 다른 legacy DB 쓰기 명령을 실행하지 않습니다.

6. V2 unit attestation, cursor handoff, 3회 clean run, timer enable

# legacy/V2 timer와 service가 모두 inactive인 상태에서 실행
test "$(/usr/local/libexec/codex-v0.146.0 --version)" = "codex-cli 0.146.0"
sudo /usr/local/sbin/newsbot-codex-containment-v1 inspect
sudo -u newsbot-codex -H /usr/local/libexec/codex-v0.146.0 login status

for unit in newsbot-collect.service newsbot-telegram.service newsbot-sheets.service newsbot-generate-codex.service; do
  sudo install -o root -g root -m 0644 \
    "/opt/newsbot/releases/$RELEASE_GIT_SHA/src/deploy/systemd/$unit" \
    "/etc/systemd/system/$unit"
done
sudo systemctl daemon-reload
for unit in newsbot-collect.service newsbot-telegram.service newsbot-sheets.service newsbot-generate-codex.service; do
  sudo systemd-analyze verify "/etc/systemd/system/$unit"
  sudo systemctl cat "$unit" | grep -F -- '/var/lib/newsbot-v2/newsbot-v2.sqlite'
done

LEGACY_OFFSET="$(sudo -u newsbot sqlite3 -readonly /var/lib/newsbot/newsbot.db \
  "SELECT next_offset FROM telegram_update_cursors WHERE stream='approval';")"
test "$LEGACY_OFFSET" -ge 0
sudo -u newsbot /usr/local/bin/newsbot v2-seed-telegram-cursor \
  --db /var/lib/newsbot-v2/newsbot-v2.sqlite --next-offset "$LEGACY_OFFSET"

for run in 1 2 3; do
  sudo systemctl start newsbot-collect.service
  sudo systemctl start newsbot-telegram.service
  sudo systemctl start newsbot-generate-codex.service
  sudo systemctl start newsbot-sheets.service
  for unit in newsbot-collect.service newsbot-telegram.service newsbot-generate-codex.service newsbot-sheets.service; do
    test "$(systemctl show "$unit" -p Result --value)" = success
  done
done

sudo systemctl enable --now newsbot-telegram.timer
sudo systemctl enable --now newsbot-sheets.timer
sudo systemctl enable --now newsbot-generate-codex.timer
sudo systemctl enable --now newsbot-collect.timer
sudo systemctl status newsbot-telegram.timer newsbot-sheets.timer newsbot-generate-codex.timer newsbot-collect.timer
sudo -u newsbot /usr/local/bin/newsbot v2-status --db /var/lib/newsbot-v2/newsbot-v2.sqlite

unit 설치·구문 검증·V2 DB 경로 attestation과 Codex containment/login 확인을 모두 끝낸 뒤 cursor를 넘깁니다. cursor seed 전에 legacy poll owner를 반드시 중지합니다. 이후 같은 Telegram bot의 두 번째 poller를 실행하지 않으며, 세 clean run이 모두 성공한 뒤에만 approval-first 순서로 timer를 활성화합니다.

7. Codex 운영 확인

sudo /usr/local/sbin/newsbot-codex-containment-v1 inspect
sudo systemctl cat newsbot-generate-codex.service \
  | grep -F -- 'generate-codex-v2-once --db /var/lib/newsbot-v2/newsbot-v2.sqlite'
sudo systemctl status newsbot-generate-codex.timer newsbot-generate-codex.service

Codex는 실제 두 단계 UID boundary입니다. device auth/provider credential은 login-shell 없는 newsbot-codex UID의 owner-only CODEX_HOME에만 있고, root-owned no-argument containment runner가 immutable authority/receipt를 attest한 작업만 실행합니다. production unit은 exact canonical request와 attempt receipt를 V2 DB에 먼저 commit하고, 검증된 output digest·정확한 draft·draft_pending_approval 전이를 한 transaction으로 commit합니다. 불명확하거나 중단된 attempt는 재실행하지 않고 manual_review로 종결합니다.

8. 실패 복구와 rollback

sudo systemctl disable --now newsbot-collect.timer newsbot-telegram.timer newsbot-sheets.timer newsbot-generate-codex.timer
for unit in newsbot-collect.service newsbot-telegram.service newsbot-sheets.service newsbot-generate-codex.service; do test "$(systemctl is-active "$unit" || true)" = inactive; done
sudo /usr/local/sbin/newsbot-codex-containment-v1 inspect
sudo -u newsbot /usr/local/bin/newsbot v2-status --db /var/lib/newsbot-v2/newsbot-v2.sqlite
sudo sh -c 'cd /var/lib/newsbot-legacy-archive/activation-17 && sha256sum -c SHA256SUMS'

urgent stop 중 Telegram·Sheets·Codex 원격 효과가 불명확하면 재시도하지 말고 timer를 멈춥니다. V2 remote-effect receipt와 운영자 확인으로만 종결하며, 확인되지 않은 효과를 재전송하지 않습니다.

rollback은 검증된 V2 release의 binary와 V2 systemd unit을 quiescence 아래 forward switch하는 작업입니다. V2 DB의 cursor, capability, attempt, delivery receipt는 보존하며 legacy DB·archive에는 activation을 append하거나 migration·restore·delete·update를 수행하지 않습니다.
