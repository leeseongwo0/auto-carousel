Newsbot 레거시 VPS 호환 배포 가이드

이 문서는 Telegram 수집·승인, Asia/Seoul 정오 처리, Google Sheets 전달, Codex 생성을 기존 방식으로 운영해야 하는 배포자를 위한 선택적 호환 가이드입니다. 일반 사용자는 README의 자격 증명 없는 수동·로컬 흐름부터 시작하십시오.

중요: 공개 저장소의 합성 채널 설정은 운영 설정이 아닙니다. REPLACE_… 값과 비공개 채널 프로필은 운영자가 별도로 검토·제공해야 하며, secret 값은 terminal, 문서, log에 붙여 넣지 마십시오. Telegram 또는 Sheets 효과가 ambiguous하면 자동으로 명령을 다시 실행하지 않습니다.

1. 소스 갱신과 release 변수

sudo git -C /opt/newsbot/current pull --ff-only origin main
cd /opt/newsbot/current
export RELEASE_GIT_SHA=REPLACE_WITH_APPROVED_40_HEX_COMMIT_SHA
export UV_SHA256=REPLACE_WITH_APPROVED_UV_ARTIFACT_SHA256
export RELEASE_DIGEST=SET_AFTER_BUILD_FROM_RUNTIME_MANIFEST_SHA256
export PROPOSAL_ID=REPLACE_WITH_NEW_OPERATOR_PROPOSAL_ID
sudo install -d -o root -g root -m 0755 /opt/newsbot/releases/$RELEASE_GIT_SHA/src
sudo git -C /opt/newsbot/current archive $RELEASE_GIT_SHA | sudo tar -x -C /opt/newsbot/releases/$RELEASE_GIT_SHA/src
sudo chown -R root:root /opt/newsbot/releases/$RELEASE_GIT_SHA

Git commit과 artifact digest는 승인된 release record에서 얻습니다. source tree, DB, session, Google JSON을 서로 복사하지 않습니다.

새 호스트에서만 DB/lock file을 release window 전에 provision합니다. 이것은 schema migration이 아니며 init-db는 switch 뒤에 실행합니다. 이후 post-007 release에서는 existing SQLite authority나 lock file을 다시 만들거나 바꾸지 않습니다.


config stage와 live file은 같은 filesystem의 /etc/newsbot 안에서만 atomic replacement합니다. 둘 다 root:newsbot, mode 0640인 regular single-link file이어야 하며, symlink, 추가 hard link, ownership/mode drift는 fail closed입니다. root만 validated semantic preimage와 manifest를 /var/lib/newsbot/config-archive에 보관합니다. 공개 status에는 현재 다섯 채널 topology만 redacted하여 표시합니다; 여섯 채널 frontier는 immutable history이고 activation 전에 authorized된 work의 traceable descendant는 grandfathered입니다.


환경 파일에는 Telegram API ID/HASH, owner-only TELEGRAM_SESSION_PATH, Bot token, approver chat/user IDs, 그 목록 안의 단 한 명인 NEWSBOT_CALLBACK_ACTOR_ID, Sheets ID 및 owner-only service-account JSON 경로를 설정합니다. secret 값 자체를 이 문서에 쓰지 마십시오.


collect/telegram/sheets의 세 service/timer 쌍은 모두 newsbot UID, 이 env file, Telethon session과 locks를 공유합니다. 이 세 worker 사이에 cross-unit isolation/private mounts는 없습니다. Signed provenance and private cross-unit isolation are explicitly out of scope.

4. backup, quiescence, versioned runtime build와 switch

sudo systemctl disable --now newsbot-collect.timer newsbot-telegram.timer newsbot-sheets.timer newsbot-generate-codex.timer
for unit in newsbot-collect.service newsbot-telegram.service newsbot-sheets.service newsbot-generate-codex.service; do test "$(systemctl is-active "$unit" || true)" = inactive; done
sudo /usr/local/sbin/newsbot-codex-containment-v1 inspect
sudo install -d -o root -g root -m 0700 /var/backups/newsbot
sudo sqlite3 /var/lib/newsbot/newsbot.db ".backup /var/backups/newsbot/newsbot-before-$RELEASE_GIT_SHA.db"
sudo chown root:root /var/backups/newsbot/newsbot-before-$RELEASE_GIT_SHA.db
sudo chmod 0600 /var/backups/newsbot/newsbot-before-$RELEASE_GIT_SHA.db
sudo sh -c 'umask 077; printf "quiescent\n" > /var/lib/newsbot/quiescence-proof'
sudo /opt/newsbot/releases/$RELEASE_GIT_SHA/src/deploy/build_newsbot_release.py --uv-sha256 $UV_SHA256 build $RELEASE_GIT_SHA --quiescence-proof /var/lib/newsbot/quiescence-proof
sudo test -f /opt/newsbot/releases/$RELEASE_GIT_SHA/runtime-manifest.json
export RELEASE_DIGEST="$(sha256sum /opt/newsbot/releases/$RELEASE_GIT_SHA/runtime-manifest.json | cut -d' ' -f1)"
sudo /opt/newsbot/releases/$RELEASE_GIT_SHA/src/deploy/build_newsbot_release.py --uv-sha256 $UV_SHA256 switch $RELEASE_GIT_SHA --quiescence-proof /var/lib/newsbot/quiescence-proof
sudo rm -f /var/lib/newsbot/quiescence-proof

현 stable release의 non-migrating helper가 build와 switch 전후에 disabled timers, inactive services, read-only application DB, collect → Telegram → Sheets canonical flock 및 Codex clean containment를 재검증합니다. legal authority drain 순서는 collect → noon → Telegram → Sheets → Codex이며, switch에서는 이 세 validated newsbot:newsbot, regular, single-link, 0600 lock descriptor를 final pre-swap check, os.replace, target attestation까지 계속 보유하며 missing/invalid/replaced lock file은 거부합니다. 따라서 switch 전에는 init-db, cutover preview/apply 또는 다른 migration-capable 명령을 실행하지 않습니다. runtime manifest의 SHA-256을 확인한 값만 RELEASE_DIGEST에 넣습니다.

preview stdout에서 proposal receipt SHA-256을 읽어 다음 변수에 정확히 넣습니다.

export PREVIEW_PROPOSAL_SHA256=REPLACE_WITH_EXACT_PREVIEW_RECEIPT_SHA256
sudo -u newsbot -H bash -c 'set -a; . /etc/newsbot/newsbot.env; set +a; exec /usr/local/bin/newsbot "$@"' _ automation-cutover-apply --config /etc/newsbot/config.toml --db /var/lib/newsbot/newsbot.db --proposal-id "$PROPOSAL_ID" --proposal-sha256 "$PREVIEW_PROPOSAL_SHA256" --release-digest "$RELEASE_DIGEST"

이 block은 최초 switch 뒤 initial schema/cutover를 위한 것이다. migration 008은 기존 Telegram outbox ID·attempt·callback·resolution 증거를 보존하면서 policy/window/config-binding authority를 추가하고 어떤 알림 작업도 backfill하지 않습니다. proposal ID, SHA-256, release digest가 하나라도 다르면 apply하지 않습니다.

# 기존 운영 DB를 6채널에서 5채널로 전환하는 후속 release에서만 실행
# workers가 quiescent인 동안 switched release와 trusted config directory를 attest하고 새 5채널 config를 같은 filesystem에 stage한다.
RELEASE_ROOT="/opt/newsbot/releases/$RELEASE_GIT_SHA"
test "$(readlink -f /usr/local/bin/newsbot)" = "$RELEASE_ROOT/venv/bin/newsbot"
sudo sh -c 'test -d /etc/newsbot && test ! -L /etc/newsbot && test "$(stat -c "%U:%G:%a" /etc/newsbot)" = "root:newsbot:750"'
sudo install -o root -g newsbot -m 0640 /secure/operator-provided-five-channel-config.toml /etc/newsbot/.config.toml.stage
sudo sh -c 'test -f /etc/newsbot/.config.toml.stage && test ! -L /etc/newsbot/.config.toml.stage && test "$(stat -c "%U:%G:%a:%h" /etc/newsbot/.config.toml.stage)" = "root:newsbot:640:1"'

# binding 전에는 exact five-of-six topology에서 config binding만 false인 drift여야 한다.
set +e
STAGED_STATUS="$(sudo -u newsbot /usr/local/bin/newsbot automation-topology-status \
  --config /etc/newsbot/.config.toml.stage --db /var/lib/newsbot/newsbot.db)"
STAGED_RC=$?
set -e
test "$STAGED_RC" = 2
printf '%s' "$STAGED_STATUS" | python3 -c 'import json,sys; actual=json.load(sys.stdin); expected={"active_cutover_present":True,"active_frontier_count":6,"config_binding_match":False,"configured_channel_count":5,"configured_channel_unique":True,"frontier_coverage":True,"frontier_shape_supported":True,"status":"drift"}; assert actual == expected, actual'

# staged bytes로 immutable activation/config binding을 먼저 append하고 receipt를 구조적으로 확인한다.
ACTIVATION_JSON="$(sudo -u newsbot /usr/local/bin/newsbot automation-release-activate \
  --config /etc/newsbot/.config.toml.stage \
  --db /var/lib/newsbot/newsbot.db \
  --release-digest "$RELEASE_DIGEST")"
ACTIVATION_ID="$(printf '%s' "$ACTIVATION_JSON" | python3 -c 'import json,sys; print(json.load(sys.stdin)["activation_id"])')"
test "$(printf '%s' "$ACTIVATION_JSON" | python3 -c 'import json,sys; print(str(json.load(sys.stdin)["changed"]).lower())')" = true

# exact config preimage와 matching runtime manifest를 activation ID 아래 root-only로 보존한다.
CONFIG_SHA256="$(sudo sha256sum /etc/newsbot/.config.toml.stage | cut -d' ' -f1)"
RUNTIME_MANIFEST="$RELEASE_ROOT/runtime-manifest.json"
RUNTIME_MANIFEST_SHA256="$(sudo sha256sum "$RUNTIME_MANIFEST" | cut -d' ' -f1)"
test "$RUNTIME_MANIFEST_SHA256" = "$RELEASE_DIGEST"
ARCHIVE_ROOT="/var/lib/newsbot/config-archive/$ACTIVATION_ID"
sudo install -d -o root -g root -m 0700 "$ARCHIVE_ROOT"
sudo install -o root -g root -m 0600 /etc/newsbot/.config.toml.stage "$ARCHIVE_ROOT/config.toml"
sudo install -o root -g root -m 0600 "$RUNTIME_MANIFEST" "$ARCHIVE_ROOT/runtime-manifest.json"
printf 'activation_id=%s\nrelease_digest=%s\nconfig_sha256=%s\nruntime_manifest_sha256=%s\n' \
  "$ACTIVATION_ID" "$RELEASE_DIGEST" "$CONFIG_SHA256" "$RUNTIME_MANIFEST_SHA256" |
  sudo tee "$ARCHIVE_ROOT/manifest" >/dev/null
sudo chown root:root "$ARCHIVE_ROOT/manifest"
sudo chmod 0600 "$ARCHIVE_ROOT/manifest"
test "$(sudo sha256sum "$ARCHIVE_ROOT/config.toml" | cut -d' ' -f1)" = "$CONFIG_SHA256"
test "$(sudo sha256sum "$ARCHIVE_ROOT/runtime-manifest.json" | cut -d' ' -f1)" = "$RUNTIME_MANIFEST_SHA256"

# 같은 filesystem에서 non-directory target으로 atomic replace하고 canonical metadata/bytes를 다시 attest한다.
sudo mv -Tf /etc/newsbot/.config.toml.stage /etc/newsbot/config.toml
sudo sh -c 'test -f /etc/newsbot/config.toml && test ! -L /etc/newsbot/config.toml && test "$(stat -c "%U:%G:%a:%h" /etc/newsbot/config.toml)" = "root:newsbot:640:1"'
test "$(sudo sha256sum /etc/newsbot/config.toml | cut -d' ' -f1)" = "$CONFIG_SHA256"

# canonical bytes는 같은 activation ID의 changed=false replay여야 하며 최종 status는 ok여야 한다.
REPLAY_JSON="$(sudo -u newsbot /usr/local/bin/newsbot automation-release-activate \
  --config /etc/newsbot/config.toml \
  --db /var/lib/newsbot/newsbot.db \
  --release-digest "$RELEASE_DIGEST")"
test "$(printf '%s' "$REPLAY_JSON" | python3 -c 'import json,sys; print(json.load(sys.stdin)["activation_id"])')" = "$ACTIVATION_ID"
test "$(printf '%s' "$REPLAY_JSON" | python3 -c 'import json,sys; print(str(json.load(sys.stdin)["changed"]).lower())')" = false
FINAL_STATUS="$(sudo -u newsbot /usr/local/bin/newsbot automation-topology-status \
  --config /etc/newsbot/config.toml \
  --db /var/lib/newsbot/newsbot.db)"
test "$(printf '%s' "$FINAL_STATUS" | python3 -c 'import json,sys; print(json.load(sys.stdin)["status"])')" = ok

세 release/cutover 명령은 stable /usr/local/bin/newsbot symlink가 가리키는 versioned runtime manifest와 현재 news_policy_v1 설정 digest를 검증합니다. preview/apply는 staged activation으로 release digest, AppConfig.digest, canonical policy payload의 immutable binding을 append합니다. latest valid five-channel release/config binding이 current authority이며, 성공 뒤 canonical replay는 같은 pair의 무변경 replay만 허용합니다. code-only·config-only·combined rollout과 rollback은 quiescence 아래 새 immutable activation/config binding을 append합니다.

urgent stop 중 Telegram/Sheets/Codex 원격 효과가 불명확하면 재시도하지 말고 timer를 멈춥니다. notification은 verified transport evidence가 있을 때만 immutable resolution 하며, Sheets는 exact metadata probe/운영자 판단만 사용합니다.

rollback은 initial cutover 후 migration-008-compatible한 이전 verified runtime release로의 forward switch입니다. 모든 worker를 disabled 상태로 유지하고 quiescence를 재검증한 뒤, 먼저 six-channel config를 해석할 수 있는 prior verified runtime으로 switch/re-attest합니다. 그 다음 root-only archive의 exact six-channel config를 같은-filesystem atomic replacement로 install/attest하고, prior runtime으로 새 release/config activation을 append/replay한 뒤에만 worker를 복구합니다. migration, cursor/outbox, noon window/items, attempts, Sheets/Telegram history, audit receipt를 DB backup으로 restore하거나 delete/update하지 않습니다.
