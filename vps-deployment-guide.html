Newsbot VPS 이전 가이드

Telegram 수집·승인, Google Sheets 전달, OAuth 기반 생성 연결을 안전하게 구성하는 순서

중요: 현재 newsbot은 OpenAI-compatible API key 방식만 구현되어 있습니다. Telegram과 Sheets는 바로 이전할 수 있지만, OAuth 생성은 OAuth gateway를 사용하거나 별도 provider를 구현해야 합니다.

먼저 이것만 보면 됩니다

  1. 로컬의 완성된 코드만 VPS의 /opt/newsbot으로 복사합니다.
  2. VPS에 newsbot 전용 사용자와 비밀 파일 디렉터리를 만듭니다.
  3. VPS에서 새 운영 DB /var/lib/newsbot/newsbot.db를 생성합니다. 로컬 데모 DB는 복사하지 않습니다.
  4. VPS에서 auth-telethon을 실행해 Telegram 계정에 한 번 로그인합니다.
  5. Telegram Bot 토큰과 승인자 ID를 설정하고 소량 수집을 시험합니다.
  6. Google 자격증명을 옮기고 Sheets validate/bootstrap을 실행합니다.
  7. OAuth gateway를 연결한 뒤 생성과 자동 실행을 활성화합니다.
핵심: 코드는 로컬에서 만들고, 실제 DB·Telegram session·자동 실행은 VPS에 둡니다.

1. 권장 디렉터리

/opt/newsbot/                 코드
/var/lib/newsbot/newsbot.db   운영 SQLite
/var/lib/newsbot/telegram/    Telethon session
/var/lib/newsbot/secrets/     OAuth token 등 회전 비밀
/etc/newsbot/newsbot.env      환경 변수
/etc/newsbot/google.json      Google service account

기존 var/demo/newsbot.db는 fixture 데이터와 실제 데모 전달 기록이 섞여 있으므로 운영 DB로 복사하지 않고 새 DB를 만듭니다.

3. 코드 전송

가장 안전한 방식은 현재 완성본을 private Git 저장소의 릴리스 커밋으로 고정한 뒤 VPS에서 clone하는 것입니다. 현재 작업 트리를 직접 전송한다면 로컬에서 다음을 실행합니다.

rsync -az \
  --exclude '.git/' \
  --exclude '.venv/' \
  --exclude '.env' \
  --exclude 'var/' \
  --exclude 'artifacts/' \
  --exclude '.pytest_cache/' \
  --exclude '.mypy_cache/' \
  ./ USER@VPS:/tmp/newsbot-release/

VPS에서:

sudo rsync -a --delete /tmp/newsbot-release/ /opt/newsbot/
sudo chown -R newsbot:newsbot /opt/newsbot
--delete는 /opt/newsbot처럼 newsbot 전용 디렉터리에만 사용합니다. .env, Telegram session, Google JSON, DB는 Git이나 코드 묶음으로 전송하지 않습니다.

4. uv와 패키지 설치

sudo -u newsbot -H bash
curl -LsSf https://astral.sh/uv/install.sh | sh
export PATH="$HOME/.local/bin:$PATH"

cd /opt/newsbot
uv sync --frozen --extra telegram --extra sheets

5. 환경 파일

sudo install -o newsbot -g newsbot -m 0600 /dev/null /etc/newsbot/newsbot.env
sudoedit /etc/newsbot/newsbot.env
NEWSBOT_DATABASE=/var/lib/newsbot/newsbot.db

TELEGRAM_API_ID=
TELEGRAM_API_HASH=
TELEGRAM_SESSION_PATH=/var/lib/newsbot/telegram/newsbot.session

TELEGRAM_BOT_TOKEN=
NEWSBOT_APPROVER_CHAT_ID=
NEWSBOT_APPROVER_USER_IDS=

GOOGLE_SHEETS_SPREADSHEET_ID=
GOOGLE_SERVICE_ACCOUNT_FILE=/etc/newsbot/google.json
값용도
TELEGRAM_API_ID / HASHTelethon을 통한 채널 뉴스 수집. my.telegram.org에서 발급합니다.
TELEGRAM_BOT_TOKEN후보·원고 알림과 승인 callback. BotFather에서 발급합니다.
APPROVER 값승인을 받을 chat ID와 허용된 Telegram user ID 목록입니다.

6. Telegram 연결

운영 DB 초기화

sudo -u newsbot -H bash
set -a
source /etc/newsbot/newsbot.env
set +a
cd /opt/newsbot

.venv/bin/newsbot init-db --db /var/lib/newsbot/newsbot.db

Telethon 최초 인증

.venv/bin/newsbot auth-telethon

전화번호, Telegram 인증 코드, 필요하면 2FA 암호를 입력합니다. 이 작업은 VPS의 대화형 터미널에서 한 번 수행합니다.

chmod 0700 /var/lib/newsbot/telegram
chmod 0600 /var/lib/newsbot/telegram/newsbot.session

소량 라이브 검증

.venv/bin/newsbot collect-live \
  --config config/channels.toml \
  --db /var/lib/newsbot/newsbot.db \
  --lookback-hours 24 --page-size 50 --max-pages 2

.venv/bin/newsbot rank \
  --config config/channels.toml \
  --db /var/lib/newsbot/newsbot.db

.venv/bin/newsbot status --db /var/lib/newsbot/newsbot.db
로컬과 VPS에서 같은 Telethon session으로 동시에 수집하지 않습니다. 초기에는 page cap을 작게 유지해 FloodWait와 대량 수집을 피합니다.

7. OAuth 생성 연결

권장: localhost OAuth gateway

OAuth gateway가 device authorization, access-token 갱신, refresh-token 저장과 upstream 호출을 담당하고, newsbot은 localhost의 OpenAI-compatible endpoint만 호출합니다.

OPENAI_BASE_URL=http://127.0.0.1:8080/v1
OPENAI_API_KEY=<gateway가 발급한 로컬 전용 토큰>
OPENAI_MODEL=<gateway 모델명>
OPENAI_TIMEOUT_SECONDS=120
  • gateway는 127.0.0.1에서만 listen
  • refresh token은 /var/lib/newsbot/secrets/에 0600으로 저장
  • 토큰과 provider 응답 본문을 로그에 남기지 않음
  • OAuth 실패 시 fake provider로 자동 fallback하지 않음

직접 OAuth provider 구현 시 필요한 값

OAUTH_ISSUER=
OAUTH_CLIENT_ID=
OAUTH_DEVICE_AUTHORIZATION_ENDPOINT=
OAUTH_TOKEN_ENDPOINT=
OAUTH_SCOPES=
OAUTH_TOKEN_FILE=/var/lib/newsbot/secrets/oauth-token.json
OAUTH_MODEL=
OAUTH_TIMEOUT_SECONDS=120
주의: 일반 OpenAI API가 서버 애플리케이션용 OAuth를 제공한다고 전제하면 안 됩니다. ChatGPT 로그인 토큰을 비공식적으로 추출하는 방식도 사용하지 않습니다. 정확한 구현은 사용할 OAuth provider의 issuer, endpoint, flow가 확정되어야 합니다.

9. systemd 자동 수집

/etc/systemd/system/newsbot-collect.service:

[Unit]
Description=Newsbot Telegram collection
After=network-online.target
Wants=network-online.target

[Service]
Type=oneshot
User=newsbot
Group=newsbot
WorkingDirectory=/opt/newsbot
EnvironmentFile=/etc/newsbot/newsbot.env
ExecStart=/opt/newsbot/.venv/bin/newsbot collect-live --config /opt/newsbot/config/channels.toml --db /var/lib/newsbot/newsbot.db --lookback-hours 24 --page-size 50 --max-pages 5
PrivateTmp=true
NoNewPrivileges=true
ProtectSystem=strict
ProtectHome=true
ReadWritePaths=/var/lib/newsbot

/etc/systemd/system/newsbot-collect.timer:

[Unit]
Description=Collect Telegram news every 10 minutes

[Timer]
OnBootSec=2min
OnUnitActiveSec=10min
Persistent=true
RandomizedDelaySec=30

[Install]
WantedBy=timers.target
sudo systemctl daemon-reload
sudo systemctl enable --now newsbot-collect.timer
systemctl list-timers 'newsbot-*'
journalctl -u newsbot-collect.service -n 100

수집, ranking, approval polling, generation, Sheets 전달을 여러 인스턴스로 동시에 실행하지 않습니다. 처음에는 oneshot timer와 공통 lock을 이용해 직렬화합니다.
