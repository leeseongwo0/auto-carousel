Newsbot VPS 쉬운 설치·운영 가이드

Telegram 수집·승인, Google Sheets 전달, Codex CLI device-auth 생성을 안전하게 구성하는 순서

BLOCK 규칙: effective permission profile 증거, cgroup-empty proof, clean/reset receipt가 참조된 containment state, migration/manifest 일치, secret/sentinel 비유출, 축소되지 않은 policy 중 하나라도 없거나 불명확하면 production을 시작하지 않습니다.

0. 먼저 이것만 보면 됩니다

  1. 로컬의 완성된 코드만 VPS의 /opt/newsbot으로 복사합니다.
  2. VPS에 newsbot 전용 사용자와 비밀 파일 디렉터리를 만듭니다.
  3. VPS에서 새 운영 DB /var/lib/newsbot/newsbot.db를 생성합니다. 로컬 데모 DB는 복사하지 않습니다.
  4. VPS에서 auth-telethon을 실행해 Telegram 계정에 한 번 로그인합니다.
  5. Telegram Bot 토큰과 승인자 ID를 설정하고 소량 수집을 시험합니다.
  6. Google 자격증명을 옮기고 Sheets validate/bootstrap을 실행합니다.
  7. newsbot-codex에서 pinned Codex device login과 containment/policy canary를 통과한 뒤 one-job 자동 실행을 활성화합니다.
핵심: 코드는 로컬에서 만들고, 실제 DB·Telegram session·자동 실행은 VPS에 둡니다.

현재 구현 상태와 원하는 전체 흐름

6개 채널 수집→중복 제거·랭킹→ Telegram 제작 여부 질문→사람의 [제작] 승인→ Codex 카드뉴스 초안→사람의 [시트 전달] 승인→ Google Sheets workplace 행 추가

결론: 각 단계의 핵심 기능과 영속 상태는 구현되어 있지만, 지금 저장소만 설치하면 이 흐름 전체가 자동으로 주기 실행되지는 않습니다. 현재 배포 artifact에는 Codex 생성 timer만 있습니다. 수집→랭킹→후보 알림, Telegram callback polling, 승인된 handoff의 Sheets 전달을 반복하는 service/timer 또는 단일 coordinator가 추가로 필요합니다.

가능 수집·평가

Telethon으로 고정된 6개 채널을 읽고 SQLite에 관찰·중복·랭킹 상태를 저장합니다.

가능 Telegram 승인

후보의 [제작] callback과 생성 원고의 [시트 전달] callback을 권한 있는 사용자에게만 허용합니다.

가능 Codex 생성

선택된 정확한 job 하나를 device-auth Codex provider로 생성하고 검토 대기 상태로 둡니다.

가능 Sheets 전달

최종 승인된 immutable handoff 하나를 고정 workplace 탭에 새 행으로 전달합니다.

추가 필요 전체 자동 스케줄

수집/랭킹/알림, callback polling, Sheets outbox 전달 timer가 아직 배포 파일로 묶이지 않았습니다.

확인 필요 AI 3 + Blockchain 3

현재 6개 handle은 고정되어 있지만 설정에는 채널별 AI/Blockchain 구분 필드가 없습니다. 특히 exilist_official은 이름상 AI 소스입니다. 정확한 3:3 목록인지 운영자가 먼저 확인해야 합니다.

승인은 두 번입니다. 첫 번째 [제작]은 생성 허가이고, 두 번째 [시트 전달]은 생성된 원고를 검토한 뒤 Google Sheets에 보낼 최종 승인입니다. 첫 승인 즉시 Sheets에 쓰는 구조가 아닙니다.

3. 코드 전송

가장 안전한 방식은 현재 완성본을 private Git 저장소의 릴리스 커밋으로 고정한 뒤 VPS에서 clone하는 것입니다. 현재 작업 트리를 직접 전송한다면 로컬에서 다음을 실행합니다.

rsync -az \
  --exclude '.git/' \
  --exclude '.venv/' \
  --exclude '.env' \
  --exclude 'var/' \
  --exclude 'artifacts/' \
  --exclude '.pytest_cache/' \
  --exclude '.mypy_cache/' \
  ./ USER@VPS:/tmp/newsbot-release/

VPS에서 B slot에만 배치합니다. release manifest가 각 executable, schema와 data artifact의 pinned checksum/owner/mode를 검증한 뒤에만 current를 atomically B로 바꿉니다.

sudo rsync -a --delete /tmp/newsbot-release/ /opt/newsbot/releases/B/
sudo chown -R root:root /opt/newsbot/releases/B
sudo ln -s /opt/newsbot/releases/B /opt/newsbot/.current-B
sudo mv -T /opt/newsbot/.current-B /opt/newsbot/current
--delete는 /opt/newsbot처럼 newsbot 전용 디렉터리에만 사용합니다. .env, Telegram session, Google JSON, DB는 Git이나 코드 묶음으로 전송하지 않습니다.

4. Python과 Newsbot 설치

release 디렉터리는 root가 소유하므로 그 안에 .venv를 만들지 않습니다. 고정된 별도 virtualenv에 설치하고 systemd가 사용하는 실행 파일을 만듭니다.

sudo apt install -y python3.12 python3.12-venv
sudo python3.12 -m venv /opt/newsbot/venv
sudo /opt/newsbot/venv/bin/pip install --upgrade pip
sudo /opt/newsbot/venv/bin/pip install \
  "/opt/newsbot/current[telegram,sheets]"

sudo install -o root -g root -m 0755 \
  /opt/newsbot/venv/bin/newsbot /usr/local/bin/newsbot
/usr/local/bin/newsbot --help

새 release마다 같은 virtualenv에 다시 설치한 뒤 /usr/local/bin/newsbot을 다시 복사합니다. uv.lock의 정확한 dependency pin을 적용하려면 staging에서 uv sync --frozen으로 wheel을 만들고 그 wheel을 이 virtualenv에 설치합니다.

운영 설정을 고정 경로에 설치

sudo install -o root -g root -m 0644 \
  /opt/newsbot/current/config/channels.toml /etc/newsbot/config.toml

sudo -u newsbot sh -c 'umask 077; exec /usr/local/bin/newsbot init-db --db /var/lib/newsbot/newsbot.db'
newsbot-generate-codex.service는 설정 경로를 /etc/newsbot/config.toml로 고정 검증합니다. 이 파일을 생략하면 Codex service는 fail closed합니다.

7. Codex CLI device auth

codex_cli는 API key/OAuth gateway가 아닌 ChatGPT device auth provider이며, 카드뉴스 생성 모델은 gpt-5.6-terra로 고정됩니다. GPT-5.6 지원을 위해 Codex CLI 0.146.0을 정확히 pin합니다.

sudo npm install -g @openai/codex@0.146.0
test "$(codex --version)" = "codex-cli 0.146.0"

sudo -u newsbot-codex -H /usr/local/bin/codex login --device-auth
sudo -u newsbot-codex -H /usr/local/bin/codex login status
sudo stat -c '%U:%G %a %n' /var/lib/newsbot-codex /var/lib/newsbot-codex/.codex

auth를 복사·출력·환경 변수화하지 않으며 Newsbot은 읽을 수 없습니다. 계정에 gpt-5.6-terra 접근 권한이 없거나 pinned CLI에서 모델 확인이 실패하면 rollout을 중단합니다.

pinned binary, runner, schema, requirements, sudoers, unit은 root-owned regular non-symlink이며 release manifest의 checksum/owner/mode와 일치해야 합니다. managed effective profile은 read-only 최소 권한이고 Newsbot/ChatGPT auth, network, web, MCP/apps/plugins, remote control, approval escalation 및 alternate /proc/FD/socket/descendant 경로를 deny한 실제 canary receipt가 필요합니다. configured intent만으로는 충분하지 않습니다.

9. 자동화 전에 전체 흐름을 수동으로 한 번 검증

아래 검증이 모두 성공하기 전에는 timer를 켜지 않습니다. 환경 파일을 읽은 newsbot shell에서 실행합니다.

sudo -u newsbot -H bash
set -a
source /etc/newsbot/newsbot.env
set +a
cd /opt/newsbot/current

# A. 새 게시물 수집 및 랭킹
/usr/local/bin/newsbot collect-live \
  --config /etc/newsbot/config.toml \
  --db /var/lib/newsbot/newsbot.db \
  --lookback-hours 24 --page-size 50 --max-pages 2
/usr/local/bin/newsbot rank \
  --config /etc/newsbot/config.toml \
  --db /var/lib/newsbot/newsbot.db

# B. 직전 rank 출력의 run_id를 넣어 후보 질문 전송
/usr/local/bin/newsbot notify-candidates \
  --db /var/lib/newsbot/newsbot.db \
  --run-id RUN_ID --actor-id APPROVER_USER_ID

# C. Telegram callback을 한 번 처리
# Telegram에서 [제작]을 누른 뒤 반복 실행
/usr/local/bin/newsbot poll-approvals \
  --config /etc/newsbot/config.toml \
  --db /var/lib/newsbot/newsbot.db \
  --timeout 20

# D. Codex 생성은 직접 runner를 실행하지 않고 service로만 실행
exit
sudo systemctl start newsbot-generate-codex.service
sudo /usr/local/sbin/newsbot-codex-containment-v1 inspect

# E. 생성된 원고 알림은 newsbot shell에서 안전하게 전송
sudo -u newsbot -H bash
set -a
source /etc/newsbot/newsbot.env
set +a
/usr/local/bin/newsbot notify-review \
  --db /var/lib/newsbot/newsbot.db \
  --candidate-id CANDIDATE_ID --generation-id GENERATION_ID \
  --actor-id APPROVER_USER_ID

# F. Telegram에서 [시트 전달]을 누른 뒤 callback 처리
/usr/local/bin/newsbot poll-approvals \
  --config /etc/newsbot/config.toml \
  --db /var/lib/newsbot/newsbot.db \
  --timeout 20

# 생성된 handoff_id를 확인한 다음 정확히 한 건 전달
/usr/local/bin/newsbot sheets-deliver \
  --config /etc/newsbot/config.toml \
  --db /var/lib/newsbot/newsbot.db \
  --handoff-id HANDOFF_ID

/usr/local/bin/newsbot sheets-status \
  --config /etc/newsbot/config.toml \
  --db /var/lib/newsbot/newsbot.db
exit
실제 자동 운영에서는 Telegram/Sheets secret을 argv나 shell history에 넣지 않고, root-owned EnvironmentFile=을 가진 전용 systemd unit으로 polling과 delivery를 실행합니다.

timer 활성화 전 체크리스트

  • 6개 채널 handle이 실제 의도한 AI 3개/Blockchain 3개와 일치한다.
  • 같은 Telethon session을 다른 PC에서 동시에 사용하지 않는다.
  • 후보 질문은 승인 그룹에만 도착하고 비승인 사용자의 callback은 거부된다.
  • Codex canary 뒤 containment가 attested clean이고 cgroup이 비어 있다.
  • 두 번째 승인 전에는 Sheets handoff/delivery가 생기지 않는다.
  • 전달 행은 정확히 workplace 탭에 한 번만 추가된다.

10. Codex one-job systemd activation과 A/B cutover

production, manual, live/canary는 직접 Newsbot/Codex/runner를 실행하지 않습니다. newsbot-generate-codex.service 한 activation은 frozen job 하나만 처리하고 newsbot-generate-codex.timer만 재발행합니다. N>1, --max-jobs, service loop는 없습니다.

# 1. timer를 멈추고 마지막 activation/cgroup이 비었는지 확인
sudo systemctl disable --now newsbot-generate-codex.timer
sudo systemctl is-active newsbot-generate-codex.service

# 2. DB backup 후 fixed artifact를 설치한다. Codex 0.146.0의 실제 resolved binary를 regular file로 복사한다.
sudo -u newsbot sqlite3 /var/lib/newsbot/newsbot.db ".backup '/var/lib/newsbot/newsbot-pre-B.db'"
test "$(codex --version)" = "codex-cli 0.146.0"
CODEX_NATIVE="$(npm root -g)/@openai/codex/node_modules/@openai/codex-linux-x64/vendor/x86_64-unknown-linux-musl/bin/codex"
test -x "$CODEX_NATIVE"
"$CODEX_NATIVE" --version
sudo install -o root -g root -m 0755 "$CODEX_NATIVE" /usr/local/libexec/codex-v0.146.0
sudo install -o root -g root -m 0755 /opt/newsbot/current/deploy/newsbot_codex_runner.py /usr/local/libexec/newsbot-codex-runner-v1
sudo install -o root -g root -m 0755 /opt/newsbot/current/deploy/newsbot_codex_containment.py /usr/local/sbin/newsbot-codex-containment-v1
sudo install -o root -g root -m 0755 /opt/newsbot/current/deploy/build_codex_manifest.py /usr/local/sbin/newsbot-build-codex-manifest-v1
sudo install -o root -g root -m 0644 /opt/newsbot/current/src/newsbot/ai/resources/copy_draft.schema.json /usr/local/share/newsbot/copy_draft.schema.json
sudo install -o root -g root -m 0644 /opt/newsbot/current/deploy/codex-requirements.toml /etc/codex/requirements.toml
sudo install -o root -g root -m 0440 /opt/newsbot/current/deploy/sudoers/newsbot-codex /etc/sudoers.d/newsbot-codex
sudo visudo -cf /etc/sudoers.d/newsbot-codex
sudo install -o root -g root -m 0644 /opt/newsbot/current/deploy/systemd/newsbot-generate-codex.service /etc/systemd/system/
sudo install -o root -g root -m 0644 /opt/newsbot/current/deploy/systemd/newsbot-generate-codex-canary.service /etc/systemd/system/
sudo install -o root -g root -m 0644 /opt/newsbot/current/deploy/systemd/newsbot-generate-codex.timer /etc/systemd/system/
sudo install -o root -g root -m 0644 /opt/newsbot/current/deploy/tmpfiles/newsbot-codex.conf /etc/tmpfiles.d/newsbot-codex.conf

# 3. persistent/runtime directory, lock, host-specific manifest를 순서대로 만든다.
sudo install -d -o root -g root -m 0700 /var/lib/newsbot-containment /var/lib/newsbot-containment/audit
sudo install -d -o root -g root -m 0755 /var/empty/newsbot-provider /var/empty/newsbot-codex
sudo install -d -o newsbot -g newsbot -m 0700 /var/lib/newsbot-canary
sudo systemd-tmpfiles --create /etc/tmpfiles.d/newsbot-codex.conf
sudo /usr/local/sbin/newsbot-build-codex-manifest-v1

# 4. migration/FK를 확인한 뒤 reset receipt로 최초 clean state를 만든다. absence는 clean이 아니다.
sudo -u newsbot sh -c 'umask 077; exec /usr/local/bin/newsbot init-db --db /var/lib/newsbot/newsbot.db'
sudo -u newsbot sh -c 'umask 077; exec /usr/local/bin/newsbot init-db --db /var/lib/newsbot-canary/newsbot.db'
sudo -u newsbot sqlite3 /var/lib/newsbot/newsbot.db 'PRAGMA foreign_key_check'
sudo /usr/local/sbin/newsbot-codex-containment-v1 reset
sudo /usr/local/sbin/newsbot-codex-containment-v1 inspect
sudo systemctl daemon-reload

# 5. provider-free Telegram/Sheets와 effective-policy negative canary 뒤 Codex canary/live를 각각 한 번만 실행한다.
sudo systemctl start newsbot-generate-codex-canary.service

11. rollback

실패하면 먼저 Codex timer와 runner activation을 중지하고 검증된 이전 A/B pin으로만 되돌립니다. DB migration은 forward-only입니다. attempts, generations, provider control/retry events, containment receipts, Sheets 행·metadata·controls를 삭제·수정·DB restore로 되돌리지 말고 교정 release와 새 immutable audit event로 전진합니다.
